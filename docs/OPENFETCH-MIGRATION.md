# OpenFetch migration from Neural Extractor V3

OpenFetch 3.1.0 is the renamed Neural Extractor V3, now presented as
**OpenFetch by Brainbyte** — open-source media downloader & toolkit.
`Brainbyte` is a brand name, not a registered company or legal entity; the
copyright holder remains `0xRootNull` (see
[PROJECT-OWNERSHIP-DECLARATION.md](PROJECT-OWNERSHIP-DECLARATION.md)).

The version continues the existing numeric line (3.0.8 → 3.1.0) instead of
restarting at 1.0.0. Installed Neural Extractor updaters compare numeric
versions, so only a higher version can reach them, and the minor increment
records the rename, the migration, and the repaired release path without
changing download behavior.

## Update feed: a two-repository bridge

The repository was renamed to **`AegisAI-Dev/OpenFetch`**. That rename cut off
every installed Neural Extractor V3 build, and this was measured against live
GitHub rather than assumed:

```text
GET https://api.github.com/repos/AegisAI-Dev/NeuralExtractor/releases/latest
  -> 301 Moved Permanently
     Location: https://api.github.com/repositories/1269465784/releases/latest
```

Installed 3.0.4-3.0.8 clients call that URL with `allow_redirects=False`.
`requests.raise_for_status()` does not raise for 3xx, so they parse the redirect
body `{"message": "Moved Permanently", ...}`, find no `tag_name`, and report
*"The latest release has an invalid version."* (`invalid_version`). Verified for
3.0.4, 3.0.7 and 3.0.8.

### What an installed Neural Extractor 3.0.x updater validates

| Rule | Value it requires |
|---|---|
| Release API | exactly `https://api.github.com/repos/AegisAI-Dev/NeuralExtractor/releases/latest`, redirects not followed, TLS verified |
| Source pinning | `UpdateChecker` raises if any other API/releases URL is supplied |
| Release state | not draft, not prerelease; tag exactly `vX.Y.Z`, numerically newer |
| Assets | exact names `NeuralExtractorV3-X.Y.Z-windows-x64.exe` and `NeuralExtractorV3-X.Y.Z-manifest.json`; optional `.sha256`; duplicate asset names rejected |
| Asset URLs | `browser_download_url` must equal `https://github.com/AegisAI-Dev/NeuralExtractor/releases/download/vX.Y.Z/<filename>` **character for character** |
| Repository identity | the slug inside those URLs only - **no repository ID is ever checked** |
| Manifest | exact field set, `schema_version` 1, `application_name` `Neural Extractor V3`, platform `windows`, architecture `x64`, channel `stable`, `release_version` = tag, `asset_filename` = the legacy EXE name, `minimum_updater_version` <= installed version |
| Integrity | GitHub asset size = manifest `asset_size`; streamed download bounded; SHA-256 compared with `hmac.compare_digest` |
| Install | target filename matches `NeuralExtractorV3(-X.Y.Z-windows-x64)?.exe`, outside temp/update roots, writable, enough disk space |
| Handoff | transaction schema 2, staged file at `<updates>/<version>/<txn>/package/<legacy EXE name>`, PID + process-creation identity, process-bound startup marker, rollback if unconfirmed |
| `html_url` | mismatch is silently corrected, never fatal |

Because only the slug is validated and no repository ID is involved, a
repository that keeps the old name serves those clients correctly. Creating it
also ends GitHub's rename redirect for that name, which is exactly what the
pinned clients need.

### The two repositories

| Repository | Role |
|---|---|
| `AegisAI-Dev/OpenFetch` | Canonical OpenFetch feed. The only source OpenFetch trusts (`openfetch.config.GITHUB_REPO`). Carries the OpenFetch asset family for 3.1.0 and every later release. |
| `AegisAI-Dev/NeuralExtractor` | Migration bridge, same owner. Keeps the pre-rename name so installed 3.0.4-3.0.8 clients reach it. Carries exactly one release, `v3.1.0`, with the legacy asset family only. |

Bridge release `v3.1.0` (built from the same executable as the canonical
release, byte-identical):

```text
NeuralExtractorV3-3.1.0-windows-x64.exe          the OpenFetch 3.1.0 executable
NeuralExtractorV3-3.1.0-manifest.json            application_name "Neural Extractor V3", minimum updater 3.0.4
NeuralExtractorV3-3.1.0-windows-x64.exe.sha256
```

Canonical release `v3.1.0` in `AegisAI-Dev/OpenFetch`:

```text
OpenFetch.exe                            convenience download, never auto-selected
OpenFetch-3.1.0-windows-x64.exe
OpenFetch-3.1.0-manifest.json            application_name "OpenFetch", minimum updater 3.1.0
OpenFetch-3.1.0-windows-x64.exe.sha256
```

Nothing is published cross-repository automatically: the release workflow
publishes the OpenFetch family in its own repository and uploads the
legacy-named family as a workflow artifact together with the exact
`gh release create --repo AegisAI-Dev/NeuralExtractor` command for the owner.

### Upgrade path

1. An installed Neural Extractor 3.0.4-3.0.8 checks the bridge repository,
   detects `v3.1.0`, selects the legacy-named EXE and manifest, and verifies
   size and SHA-256.
2. Its detached helper replaces `NeuralExtractorV3.exe` in place with the
   OpenFetch executable and starts it with the legacy transaction reference.
3. OpenFetch accepts that transaction below
   `%LOCALAPPDATA%\NeuralExtractorV3\updates`, writes the process-bound startup
   confirmation, and the old helper finalizes the update. If OpenFetch fails to
   confirm, the old helper restores Neural Extractor exactly as before.
4. On first start OpenFetch copies settings and durable data (below) and, on the
   next ordinary start, reclaims the finished legacy update state. The file keeps
   its `NeuralExtractorV3.exe` name so existing shortcuts keep working.
5. From then on OpenFetch checks **`AegisAI-Dev/OpenFetch`** only. 3.1.1 and
   later need no bridge release; the bridge can be archived once telemetry-free
   judgement says the remaining 3.0.x installations have migrated.

Neural Extractor 3.0.2/3.0.3 still need the manual 3.0.4-era step documented in
[UPDATE_ARCHITECTURE.md](UPDATE_ARCHITECTURE.md); older builds cannot self-update.

### Security properties preserved

* Redirects are still never followed; a 3xx answer is classified
  (`release_source_moved`) instead of parsed, and a missing feed is
  `release_source_unavailable`.
* Both repositories are owned by `AegisAI-Dev`; no unrelated namespace is
  trusted, and the GitHub login `BrainByte` (an unrelated account) is not used.
* Manifest validation, SHA-256 verification, executable-identity checks,
  transaction confirmation and rollback are unchanged.
* OpenFetch cannot be repointed at the bridge: `UpdateChecker` rejects any
  non-canonical API or releases URL.

## User data migration

On first start OpenFetch (GUI, CLI and diagnostics) copies from
`%LOCALAPPDATA%\NeuralExtractorV3`:

- `youtube\` — dedicated Chrome/Firefox sign-in profiles, without browser caches
  and lock files;
- `optional-po-provider\` — the external helper activation manifest;

and copies `HKCU\Software\Neuralshield\NeuralExtractorV3` into
`HKCU\Software\Brainbyte\OpenFetch`, rewriting stored paths that pointed into
the legacy data directory and skipping browser process identities.

Transient state (`updates`, `updater-helper`, `process-state`, `worker-temp`)
is not copied. Finished legacy update state - the transaction, the staged
package and the detached helper copy the old updater left behind, together the
size of a release - is reclaimed on the next ordinary start after the upgrade;
an unfinished legacy transaction is never touched. Nothing is moved or deleted, existing OpenFetch data is never
overwritten, completed items are recorded in `legacy-migration.json` and the
settings marker `migration/neural_extractor_v3`, and a copy interrupted by an
error is discarded and retried on the next start. `legacy-migration.log` lists
item names and counts only.

## Releasing 3.1.0 (owner approval required)

Nothing is published by the migration work itself. When approved:

1. Merge the migration branch into the default branch.
2. Confirm tag `v3.1.0` does not exist.
3. In GitHub Actions run **Owner-Authorized OpenFetch One-File Release** from
   the default branch of `AegisAI-Dev/OpenFetch`, with version `3.1.0` and
   confirmation `PUBLISH-OPENFETCH-3.1.0`.
4. The workflow validates versions, runs tests and manifest checks, builds
   `OpenFetch-onefile.spec`, runs packaged runtime/GUI/provider/updater smokes,
   scans for prohibited payloads, generates both asset families and both
   manifests, verifies them against the final EXE, and publishes a stable
   release.
5. Create the bridge repository `AegisAI-Dev/NeuralExtractor` (this also ends
   GitHub's rename redirect for that name) and publish its single `v3.1.0`
   release with the three legacy-named assets from the workflow artifact, using
   the `gh release create ... --repo AegisAI-Dev/NeuralExtractor --latest`
   command the workflow prints.
6. On a clean Windows profile, verify both manifests and checksums, then test the
   in-app update from an installed Neural Extractor 3.0.8 and confirm the
   upgraded application checks `AegisAI-Dev/OpenFetch`.

The compliance-gated one-folder workflow (`build-release.yml`) remains
fail-closed while the licensing verdict is HOLD.
